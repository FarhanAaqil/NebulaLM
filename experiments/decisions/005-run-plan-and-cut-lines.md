# 005 — Run plan, cut-lines, and what is left to people

Date: 2026-11-11

## Decision

The study runs the blueprint's P0 and P1 tiers only. `scripts/run_queue.py` is the registered order; `python scripts/run_queue.py --list` prints it.

| Tier | Experiment | Runs |
|---|---|---|
| P0 | EXP-TOK-production | 4 tokenizer candidates, one 10.3M proxy pass each (protocol registered separately) |
| P0 | EXP-LR | 4.5M, 10.3M, 29.4M at peak LR 1e-4, 3e-4, 1e-3, half a pass each (1.5 D per size) |
| P0 | EXP-GRID | 10.3M and 29.4M: M0 trunk to 6.4 passes, cooldown branches at 1, 2, 4, 8 |
| P0 | BRANCH-EQ | standalone 10.3M one-pass run with the trunk's seed and data order |
| P0 | 5-gram | interpolated Kneser-Ney, order sweep 3 to 6, same tokens |
| P1 | EXP-LEAK | the same grid on M1 (M0 plus probe siblings) |
| P1 | ARM-4M | 4.5M: M0 trunk and branches |
| P1 | EXP-RVU | 4 passes over D/4 and 8 passes over D/8 unique documents, 10.3M and 29.4M |
| P1 | EXP-SEED | two more seeds for 10.3M and 29.4M at 1 and 4 passes |

Rules fixed here, before any run:

1. **LR per size** is the lowest validation BPB after half a pass; within 1 percent, the smaller LR. It is written to `experiments/records/EXP-LR.json` before any grid run starts.
2. **Branches.** A branch for E passes resumes the trunk's checkpoint at 0.8 E passes (same weights, optimizer state, data position, and RNG) and decays over the last 20 percent. Until that step the schedules are identical, so a branch is the same computation as a standalone run up to floating-point nondeterminism on the GPU. BRANCH-EQ measures that difference; it must sit inside the seed spread.
3. **Precision.** FP16 autocast with GradScaler. A diverging run is repeated once at half the LR and logged as a deviation (blueprint rule 6).
4. **Test stays sealed** until every run in the queue is finished or declared cut. The campaign reads it once per registered checkpoint through `scripts/audit_checkpoint.py --final-evaluation-campaign`, and every read is logged.

## Cut, by the blueprint's cut-lines

- Gutenberg challenge set (cut-line 1; already deferred in decision 004).
- P3: capacity curve, naive-split neural run, Pythia reference.
- P2: cosine check (EXP-SCHED), span-type BPB (H4), cloze pools and minimal-pair items (H5). H4 and H5 are reported as not run.
- The digit-split tokenizer stays, because it costs one proxy pass inside EXP-TOK.

## Left to people

- **H1c (generation quality)** needs human ratings: 120 sampled outputs, 40 double-rated by the author and one volunteer. The samples are generated by the campaign; the ratings are not something code can supply, so H1c stays open until they exist.
- Legal review of any release of weights.

## Rejected alternative

Running P2 items in the gaps of the queue. A solo schedule with roughly a day of GPU time does not have gaps; the blueprint says to cut P2 and P3 first.
